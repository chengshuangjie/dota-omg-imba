## 1. IMBA 模式入口（定位结论）

“IMBA”在本图**不是一个玩家侧技能倍率开关**，而是一组“默认 OMG 难度 + AI 强化”的模式位。

### 1.1 默认模式串（真正的入口）
- 行 57374-57377：`-omg` → `NQ9="-sdxmfrstscmccnpm"`，`FastMode=1`。
- 模式位表 57384-57504：槽 47 = `xtrememode`=`xm`（行 57476-57477）。
- 解析后行 57612：`set XM=NU9[47]`。
- 行 58058-58065：`if XM then set XM_MODE=true; HG=true; DE=true; DG=true; DG0=true; call ExecuteFunc("C0FD")`。
  - 即 **xm 默认开启**（模式串里含 "xm"）→ `XM_MODE` 默认 true。

### 1.2 `XM_MODE` 到底影响什么（33 处消费点全部盘点）
`XM_MODE` 出现 33 次，**全部是 AI 行为/解锁**，无一修改玩家技能数值：
- AI 16/22/25 级自动升级/买阿哈利姆：行 37950/37954/37961、45051/45054/45057、135526/135530、137563、152948、209415。
- AI 抽卡/抽奖行为：37932、209440。
- AI 动态难度相关：52976、53023(`Y48==19`)、226636、227474、127948。
- 等级 25 触发的 AI 逻辑：20368、133495/133508/133514。

**结论：当前没有任何“玩家技能伤害/治疗/范围/时长”的全局倍率。** 本次 ×2 是第一个，不存在历史叠乘（仅存在下文 §4 的局部倍率）。

### 1.3 KK 难度对话框（主机开局三选一）
- 声明：行 613-617（`KK_GAME_DIFFICULTY=0` + NEWBIE/NORMAL/HARD 按钮）。
- 应用函数：`KKDifficulty_Apply` 行 58231-58266；点击 58267；超时默认 2（行 58278-58283）。

| 值 | 档 | 行为 |
|---|---|---|
| 0 | 未选 | —（15s 超时自动落 2） |
| 1 | 新手 | 行 58236-58249：**强制** `XM_MODE=false`、`XM_EXP=0`、`XM_GOLD=0`、`XM_CG=false`、`CT=false`、`WT=true`、`DG0=false`、`EU/FU/FUCK=false`、`Gw=Gv=true`；并 `KKDifficulty_StartNewbieSpeedCap()`（AI 移速上限 350、攻速上限 3.5，行 58136-58154）。 |
| 2 | 普通（默认） | 不动 `XM_MODE`（=true，来自默认串），无 AI 额外经验/金钱。 |
| 3 | 困难 | 行 58251-58257：`XM_EXP=5`、`XM_GOLD=5`（AI 动态经验/金钱 +50%）、`XM_CG=true`、`FUCK=true`（AI 更激进用技能/装备，见 149516/151306/152789…）。**不改 `XM_MODE`。** |

### 1.4 其他开关
- `-neng`/`neng`（行 58095-58116 `OmgNengCommand_Action`）：**只能关** `XM_MODE`，没有再开启路径。
- `FUCK`（“法克模式”）：纯 AI 进攻性/出装行为，32 处消费全是 AI 决策，与玩家数值无关。
- `B979Mode`（AI 技能组合 1=普通/2=高难，行 58162-58229）：只影响 AI 抽技能库，不改玩家数值。

## 2. 技能参数体系与初始化数据（结构结论）

### 2.1 唯一集中式数据表 = 蓝耗（必须排除）
- `hashtable B945SpellData`（行 31）；`B945LoadData` 解析（10780-10805）；`B945InitSpellData` 加载 Block0..89（11076-11171）。
- 读取点仅两个：
  - `B945DefinitionMana(skill, rank)` 行 11172-11180 → `LoadInteger(B945SpellData, skill, rank)`，**即每级蓝耗**（Block0-87，整数模式）。特例 `'A0MP'`/`'Y05U'` 返回 0。
  - Block88-89（布尔模式）= 物品→技能授予映射（`B945SourceItem` 11181-11198；运行时另见 229371-229393 的 SaveBoolean 链）。
- **该表是蓝耗，禁止 ×2。**

### 2.2 集中式“伤害出口” = `B67`（唯一可集中改伤害的点）
- `function B67 takes unit p5(源), unit m5(目标), integer BL7(伤害类型), real YM7(数值)` 行 28377-28457。
- 调用点 **442 处**。`YM7` 三种来源：
  - 硬编码字面量：`B67(...,1,160)`(28533)、`B67(...,2,85)`(46453)、`B67(...,3,400/500/600)`(47889-47893)。
  - 等级公式：`B67(...,2,40+20*GetUnitAbilityLevel(...))`(28513)、`B67(...,10,20*GetUnitAbilityLevel(...))`(28528)。
  - 变量透传：`B67(...,1,YM7)`、`B67(...,1,d)`。
- `BL7` 伤害类型 1..21（注释见 28385-28453）。其中：
  - `BL7==6`（行 28402-28410）= 生命移除 `SetUnitState(...LIFE, life-YM7)`，低血时用 `'e00E'` 假人打 1e8 真伤执行——**该假人伤害不走 `YM7`**。
  - `BL7==3`(行 28393-28395) 与 `BL7==7`(行 28413-28415) **已内置** `if IsFortDefenseTypeUnit(m5) then set YM7=YM7*2`。

### 2.3 集中式“治疗出口”
- `B907SkillHeal(src,dst,amount)` → `B907ApplySkillHeal` 行 26762-26808；实际加血 `SetUnitState(healTarget, UNIT_STATE_LIFE, healBefore+healAmount)` 在 **26783**。
- 旧版简口 `YQ7(hn,iS)` 行 26812-26814（直接 +iS）。
- **未走集中口的治疗**：26582、26609（`+ON7(...,"Damage")`）、40736（`.9*GetEventDamage()` 吸血）、73867（`QM_Restore_LIFE`）、240018/240081（套装回血）。

### 2.4 集中式“眩晕时长”出口
- `CommonUnitAddStun(unit, dur, isIgnoresMI)` 行 28487-28510：建假人 `'e00E'` 加 `'A420'`，写 `ABILITY_DATA_DUR`/`HERODUR=dur`。
- 已有保护：`MiaoStarted`(28489)、`ChaosObserverBoss/TianxingBlackBoss`(28492)、魔免(28495) 直接 return 0。

### 2.5 DoT 周期伤害
- `Loop_Damage(src,dst,period,dur,amount)` 行 28476-28485：每 `period` 秒打一次 `B67(src,dst,1,amount)`(28470)，结束时刻存 `TABLE_HY[child 100]=GetGameTime()+dur`(28482)。
- **`period`(节拍) ≠ 持续时长**：只能动 `dur`，绝不能动 `period`。

### 2.6 范围 / 距离 —— 无集中口（不可安全集中改）
- `MHUnit_GetSpellRange/AddSpellRange`（9977-9984）是**空桩**（`return 0` / `ConvertRace(0)`）。
- `B848_FormBaseRange/SetFormRange`（78323-78341）只处理变身形态的**攻击距离**随机化，不是施法距离。
- 施法/搜索/跳跃/弹射距离全部是各技能里的字面量（`GroupEnumUnitsInRange*` 675 处）。**无字段级集中点。**

### 2.7 概率
- 各函数自带封顶，如 `BrewmasterBrawler_CritRate`（14142-14154）：`chance=(5+5*level)/100`，`RMinBJ(chance,.45)`，神杖直接 `return 1.`；`TryCrit`(14156-14162) 已有 `if rate>=100. return true`。
- **概率类不做盲 ×2**；若要加，一律 `RMinBJ(原值*mult,1.0)` 封顶 100%。

## 3. 字段级 ×2 语义清单（可执行）

> 设计原则：**集中式、字段级、每参数只乘一次**，用一个全局开关 `boolean IMBA_POWER=false` + 倍率常量。下面给出“插哪一行、改什么、现状值”。

### 3.1 应 ×2 且有安全集中点的（推荐首批）

| 参数 | 集中函数/行 | 现状 | 建议插入点 | 说明 |
|---|---|---|---|---|
| **技能伤害** | `B67` 行 28380-28382（`if BL7==0 then return` 之后） | 无倍率 | `if IMBA_POWER and BL7!=6 then set YM7=YM7*IMBA_DMG_MULT endif`（`IMBA_DMG_MULT=2.`） | 一处覆盖 442 个调用。**BL7==6 生命移除另行处理**（见风险 R2）。 |
| **技能治疗** | `B907ApplySkillHeal` 行 26781-26783（`SetUnitState` 之前） | 已有树枝 `I7AA` ×1.15 | `if IMBA_POWER then set healAmount=healAmount*IMBA_HEAL_MULT endif`，随后必须夹到 `RMinBJ(healAmount, 最大生命-healBefore)` 防过量。 | 不覆盖 §2.3 列出的旁路治疗。 |
| **眩晕/控制时长** | `CommonUnitAddStun` 行 28499（`if dur>0` 内） | 字面量 0.4~1.4s | `if IMBA_POWER then set dur=RMinBJ(dur*IMBA_DUR_MULT, 5.0) endif` | 加 5s 安全帽防 stun-lock；已有 Boss/魔免免疫 return 不受影响。 |

### 3.2 应 ×2 但**无集中点**，只能逐个技能改（第二批，需人工）
- **施法/搜索/弹射/跳跃距离**：无集中口，每技能一个字面量，×2 需逐技能定位。
- **DoT/Buff 持续时间**：287 处 `TimerStart`，时长多为字面量；`Loop_Damage` 的 `dur` 可集中乘，但其它 buff 定时器不集中。
- **次数/数量**（弹射次数、召唤数量、弹道数）：散落字面量，无表。
- **概率**：仅在“原值<0.5”的技能上 `RMinBJ(原值*2,1.0)`，逐技能判定。

### 3.3 必须排除（不可 ×2）
- **蓝耗**：`B945DefinitionMana` / `B945SpellData`（§2.1）。
- **冷却**：在单位数据（SLK/物编），脚本里没有集中冷却数值；本改造不碰。
- **负面自伤/反伤**：`B67` 中 `p5==m5` 的自伤调用、`BL7==6` 生命移除的自残分支、吸血 `.9*GetEventDamage()`(40736) 的反向结算——**需人工枚举 `p5==m5` 的调用点后排除**（rg 不支持反向引用，未自动枚举）。
- **模型缩放/对象 ID/句柄/数组索引/计时器/坐标**：`'e00E'`、`'A420'`、`'A420'`、`GetHandleId`、`TABLE_HY` child 槽位、`TimerStart` 的 `period`、单位 XY——一律不乘。
- **`Loop_Damage` 的 `period`**（节拍）：只乘 `dur`。
- **AI 经验/金钱 handicap**：`XM_EXP/XM_GOLD`（行 163955/164008）是 AI 侧，不属玩家技能参数。
- **Fort 防御规则**：`IsFortDefenseTypeUnit` 的减伤/加倍（见 §4）。

## 5. 持续时间永久化 / 安全上限风险

- **R1 眩晕 stun-lock**：`CommonUnitAddStun` 时长 ×2 后，0.4s→0.8s、1.4s→2.8s 尚可，但组合多段控制会锁死。**必须加帽**（建议 5s，见 §3.1）。Boss 已免疫（28492），新手/普通玩家 PvP 需实测。
- **R2 `BL7==6` 生命移除**：`SetUnitState(LIFE, life-YM7)` 是真实扣血、无视护甲魔抗；全局 ×2 会让生命移除类技能（如殉节/血池）伤害翻倍且**绕过伤害类型判定**。建议 `BL7==6` 不进全局乘式，单独白名单。
- **R3 治疗过量**：26783 用 `healBefore+healAmount`，未夹到最大生命；×2 后会过量治疗。必须夹 `RMinBJ(healAmount, 最大生命-healBefore)`。
- **R4 定时器生命周期错配**：`Loop_Damage` 的结束时刻 `child100=now+dur` 与 `dur` 同源，集中乘 `dur` 是安全的；但其它 `TimerStart(t, dur, true, ...)` 若循环体内部还按“固定 tick 数”结算（如预期 N 次），×2 时长会导致多打 N 次。**凡改 buff 时长，必须核对对应 cleanup（FlushChildHashtable/DestroyTimer）是否按 game-time 退出**，否则残留定时器 = 句柄泄漏/崩溃。
- **R5 永久化**：当前没有任何“时长=永久”的参数；但 ×2 若作用在“短时长 buff”上，注意别把 0.01s（金箍棒行 28534）乘成 0.02s 这类无意义放大——短时长阈值（如 `<0.1s`）应跳过。

## 6. 未覆盖技能及原因（不猜）

1. **未走 `B67` 的直伤**：脚本里另有约 223 处 `UnitDamagePoint/UnitDamageTarget`（计数自 `UnitDamagePoint|UnitDamageTarget|BlzSetEventDamage|EventDamage(`），这些**绕过 B67**，全局伤害乘式对它们无效。需逐处确认是否为技能直伤后再决定是否纳入。
2. **旁路治疗**（§2.3 列的 6 处）：不走 `B907`，全局治疗乘式不覆盖。
3. **范围/弹射/召唤数/buff 时长**：无集中点（§2.6），全量 ×2 无法安全证明，本批不做。
4. **原生物编技能**：数值在 SLK/物编里（脚本不可见），本脚本层 ×2 不覆盖。
5. **`p5==m5` 自伤调用**：未自动枚举（rg 无反向引用），实施前需人工列清单并从伤害乘式排除。

> 结论：**可安全自动覆盖的范围 = 经 `B67` 的技能伤害（排除 BL7==6）+ 经 `B907SkillHeal` 的治疗（加过量夹）+ 经 `CommonUnitAddStun` 的眩晕（加 5s 帽）**。其余一律列为第二批人工逐技能。

## 7. 静态同步 / 崩溃验收点

- **S1 同步确定性**：`IMBA_POWER` 必须是开局模式选择时由**主机对话框/模式串**写入、并随同步链广播到所有客户端的全局；**禁止**用 `GetLocalPlayer()` 本地决定，否则各端伤害不一致 = 脱战/崩溃。参考本图 B1060 预测/同步架构（行 11346 注释：混合事件回调不得在 timer/order 事件上查伤害载荷）。
- **S2 作用域**：乘式只放在 `B67`/`B907ApplySkillHeal`/`CommonUnitAddStun` 三个已同步函数内；不在 timer 回调、order 回调里新增伤害判定。
- **S3 PJASS**：构建脚本 `tools/build/build.ps1` 会跑 PJASS，仅允许既有 `location_m5` 未初始化告警；新增代码不得引入新的未初始化/类型错误。
- **S4 包内回读**：构建后必须 `verify.ps1` 从成品 w3x 回读 SHA 比对，不能只看 MPQEditor 退出码。
- **S5 不破坏既有链**：
  - 保留进图奖励、`-recharge`、`-rlog`；
  - 不得出现后加皮肤路径、车轮战、30 波防守（build.ps1 会查禁用短语）；
  - `B945SpellData` 蓝耗表只读不改。
- **S6 数值边界**：倍率常量集中定义一次（`real IMBA_DMG_MULT=2.` 等），全工程只允许在三个插入点出现这一次乘法；grep 复核无第二处 `*2` 散点。
- **S7 句柄安全**：`CommonUnitAddStun` 改动后，假人 `'e00E'` 的 `UnitApplyTimedLife('BTLF',1.)` 路径不变；时长乘完仍 >0 才建假人（保持 `if dur>0`）。
- **S8 回归点**：新手档(1) 应维持 `XM_MODE=false` 且 AI 速度上限 350；困难档(3) 仍只加 AI handicap，不被玩家 ×2 误伤 AI。
