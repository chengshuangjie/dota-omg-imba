八、XOMG1 存档协议（键隔离 + v1 信封 + 零迁移）

8.1 设计原则

  • 所有 ServerValue / Stat 实际键统一隔离到 XOMG1_ 命名空间；新键为空档 = 全新状态，绝不读取任何旧键、不保留迁移分支。
  • 空新键在内存生成默认 v1 记录，首次进图不主动写服务器；仅在合法业务变更时经 CAS 写。
  • 未知版本 / 非空损坏 / API 错误 → fail-closed：锁定该记录本局写入，玩家提示 + B1133 本地诊断（B1133LogAppend）。不以 S2I 吞错后写 0。
  • 记录长度 ≤63 字节（B836ArcValid / arcLength 校验）；动态键（英雄/peer）做白名单与长度检查。

8.2 旧键 → 新键映射（全部已落地，旧键字面量 src=0）

8.3 实际 v1 格式

  • 设置类（SETUP/HOTKEY/SPELL）：外层字面 "1;"+<原字符串>；读取时剥离 "1;" 前缀，无前缀/损坏 = 内存默认、不写覆盖。写入即 "1;" 信封。
  • ARC / QUIT / TIP / TR / M_：复用既有自带版本前缀的线路格式（ARC 内层版本号 1..5、QUIT 日志版本 1/2/3、境界 pack、打赏回执），本身即自描述版本记录；新键空档首次业务写才生成，≤63B，CAS 写后回读、有限重试3次、故障锁。
  • 计数（ZTTP/WINS/MVP）：沿用既有 StoredInteger + Stat 同步，写入前经 GetServerValueErrorCode 与边界校验（不在错误时写0）。
