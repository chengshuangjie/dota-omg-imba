# noskin18 联机装备不同步定位与 noskin19 修复报告

## 结论

noskin18 不应继续用于联机。已定位到新增的“野怪装备鼠标左键双击出售”本地鼠标回调存在确定性同步风险：

1. 点击者客户端在 `GetLocalPlayer()` 路径中创建 `Rect` 和 `Condition` 句柄；其他客户端不会执行同样的句柄创建。
2. 本地回调还枚举物品、读取物品 handle，并把本机的物品 handle ID 放入 `DROP_SELL` 同步消息。
3. 当各客户端句柄序列产生差异后，同一个 handle ID 可能对应不同对象或无法对应同一物品，导致某客户端删除装备、另一个客户端不删除或选中另一件装备。
4. 这与实机现象一致：运行一段时间后，双方看到彼此装备内容不同。

这不是普通UI显示偏差，而是客户端游戏状态已经分叉。已经分叉的旧对局无法在局内恢复，必须使用修复地图重新开局。

## noskin19 修改范围

基于 noskin18，只修改双击出售的同步闭包：

- 本地鼠标回调只读取本地点击时间和鼠标地形坐标。
- 本地回调不再创建 `Rect`、`Condition` 或其他 Warcraft 句柄。
- 本地回调不再枚举、选中或读取物品 handle。
- `DROP_SELL` 消息只发送玩家编号和点击坐标，不发送本地物品 handle。
- 所有客户端在同一个 `DROP_SELL` 同步回调中统一枚举同一区域、选择物品、删除物品和增加金币。
- 将双击时间改为按玩家存储，避免不同玩家共用一个点击时间变量。
- 枚举完成后释放 `boolexpr` 和 `rect`，修复后期逐渐卡顿的句柄泄漏。
- 内置地图名改为唯一的 `OMG IMBA v1.8.5-SYNCF001`，避免KK复用旧缓存。

## 静态验证

- PJASS：除基线既有的 `location_m5 未初始化`外，无新增错误。
- 相对noskin18：只修改3个函数：
  - `B1063SellMouseDown`
  - `B1063SellPickNearest`
  - `B1063SellSync`
- 函数总数不变：8885。
- `DzTriggerRegisterSyncData`数量不变。
- `TimerStart`数量不变。
- 本地鼠标回调安全门全部通过：无 `Rect`、无 `Condition`、无物品枚举、无 handle 读取、无物品增删、无日志写盘。
- 同步回调包含统一枚举、出售、加钱，并释放 `Rect`/`boolexpr`。
- W3I仍为806字节，仅两个24字节名称槽变化，槽外差异为0。
- 最终W3X回提的脚本和W3I与工作文件SHA-256完全一致。
- AbilityData、Campaign文本、全部Unit SLK、导入表和K的模型/肖像/纹理与noskin18逐字节一致。

## 实机验收重点

1. 必须两名真人使用noskin19重新开局，不能继续旧的noskin18对局。
2. 游戏中双方分别购买、拾取、丢弃装备，并互相观察装备栏。
3. 多次使用野怪地面装备双击出售，确认双方同时看到物品消失且售出者金币一致。
4. 建议至少游玩到10分钟后，再互相比较双方英雄装备。
5. 如果仍有分叉，记录首次出现差异的大致时间、刚执行的动作和双方截图，再结合新版本日志继续定位。

当前结论为：静态同步风险已修复，仍需双人实机验证才能确认联机完全通过。
